## 新增 CheckBox 组件（MD3 风格，基于 ark-ui）

- 文件：`libs/components/CheckBox.tsx`；演示加在 `src/App.tsx`。
- 结构仿 `Switch.tsx`：`Checkbox.Root/Control/Indicator/Label/HiddenInput` + `splitProps(['class','children'])` + `classNames` + `css` 嵌套，children 作为可选 label。
- keystone 规格：容器 18×18dp、2dp 圆角、2dp 描边；状态层 40dp 圆形（hover .08 / focus-visible .1 / active .1，用 currentColor 复用色槽）；勾选图标是 `<polyline points="4 9 7.5 12.5 14 6">`（18 viewBox + stroke-width 2，45° Material 勾）；indeterminate 用 Indicator 的 `::before` 短横线（10×2）。
- 关键技巧：Indicator 用 `position:absolute; inset:-2px` 撑满 control 的 border box（避开 flex 负空间的居中歧义）；`display:block` 覆盖 Ark 的 `[hidden]`，否则勾选动画无法过渡。
- 复用 Switch 调色板：primary `#596400`、outline `#78786a`、on-primary `#fff`；disabled opacity .38（MD3）。
- 类型检查：`node_modules/.bin/tsc --noEmit -p tsconfig.app.json` 通过；仅剩历史遗留错误 `src/App.tsx` 未使用的 `createSignal`（未改动）。

## 修复：状态层圆环水平偏右 13px

- 现象：hover 圆环不居中。用 PIL 量截图（2x）拟合出圆心 (69.5, 49.4)、R=19.8 CSS px，绿框中心 (43.5, 49.5) → **垂直对齐、水平偏右 13px**。
- 根因：`position: absolute` + `inset: 0` + `margin: auto` 只在**子元素小于包含块**时能居中。控制框 18px + 2px 边框 → padding box 仅 14px，40px 圆环大于容器：
  - 水平（CSS 10.3.7）有"负 margin 例外" → `margin-left: 0`，塌到 padding box 左边 → 圆心 2+20=22，比中心 9 多 13px（与实测完全吻合）；
  - 垂直（CSS 10.6.4）**没有**该例外 → 两 auto 取相等值，允许负 margin，所以仍然居中。
- 修法：改为 `top: 50%; left: 50%; transform: translate(-50%, -50%)`，与元素尺寸无关。
- 教训：`inset: 0; margin: auto` 这种居中写法对"大于容器的溢出元素"不成立（本项目其他自由尺寸的小图标仍可继续用）；负 inset（如 Indicator 的 `inset: -2px`）做拉伸是安全的。

## 改用 Ripple 组件做状态层（用户要求）

- 用户指出：**CheckBox 的 hover 背板不能用伪元素**，否则没有水波纹；Switch 用伪元素是因为 MD3 的 Switch 本来就没有 ripple。规范分工：Switch 无 ripple，CheckBox 要有。
- 结构：`Control > div[data-part=backplate]（40dp 圆，承载 Ripple） + Indicator`，背板在前（DOM 顺序=绘制顺序，波纹在勾之下）。
- Ripple 用法要点（读源码得出）：
  - 容器 `border-radius: inherit` + `overflow: hidden` → 形状由背板给，即"背板定形、Ripple 填充"，所以 Ripple 必须是背板的子元素；
  - `parent = container.parentElement` → **背板即交互宿主**，pointerenter/down 都绑在背板上，40dp 圆正好是 MD3 的状态层/触控范围；
  - hover 图层由 Ripple 自带 mask 管 → 覆盖 `--s-ripple-hover-opacity: 0.08`；按压波纹峰值 → `--s-ripple-opacity: 0.1`（均取 MD3 值）；
  - 它暴露 `hover` / `pressed` 属性给宿主，但**无 focus 处理**（纯 pointer 驱动）→ 键盘聚焦态用背板 `background-color: color-mix(in srgb, currentColor 10%, transparent)` 补；用 background 而非 opacity，是因为背板里装着 Ripple，改 opacity 会一起压暗波纹。
  - disabled 用 `&[data-disabled] [data-part='backplate'] { display: none }` 一行覆盖 hover/波纹/命中区，不必再传 Ripple 的 `disabled`/`disabledHover`。
- **重要发现**：`solid-styled-components` 直接 re-export goober 的 `css`；goober **在 JS 里自己做嵌套扁平化**（`&` 与无 `&` 的嵌套都会补上父选择器前缀），**不依赖浏览器原生 CSS 嵌套**，所以嵌套写法不受 relaxed nesting 版本限制。
- 校验手段：goober 在 Node 下有 SSR 分支（`getSheet` 无 window 时返回内存 sheet），可 `createRequire(项目 package.json)('goober')` + `css({raw:[...]})` + `extractCss()` 直接打印真实产出 CSS，无需浏览器。以后改样式可复用这招。
  - ⚠️ **上面这个 `css({raw:[...]})` 写法是错的，见本文件末尾的纠正。**


## 规范化 Slider 样式模板的嵌套层次 + 离线校验级联

- 用户要求「把 Slider 的样式规范化一下，嵌套层次有点乱」。原版把 `[data-part='track']`/`[data-part='thumb']` 嵌在 `[data-part='control']` 里，还在 track 内部再嵌一层 `&[data-orientation='vertical']` 特例 → 三层嵌套 + 一次性特例，改一处要跳三层、特例容易被忽略。
- 现在 `libs/components/Slider.tsx` 的 `rootClassName` 拍平成三段（顶层并列，最深两层）：
  1. **尺寸**：`&[data-orientation='horizontal'|'vertical']` 各自给 root 定宽高
  2. **共用**：`[data-part='control']` / `[data-part='track']` / `[data-part='thumb']` 的形状与配色（track 底 #e3e5c2、range-left #596400、thumb 的 `::before` 选中圆 + `::after` 状态层 + hover/dragging 放大 200%）
  3. **几何**：两个 `&[data-orientation='...']` 块，各自覆盖 track 的 flex 方向、range-left/right 的轴向 CSS 变量、thumb 的定位与尺寸基准
- 覆盖不依赖声明顺序，依赖特异性：朝向块比共用块多一层 `[data-orientation]` 属性 → 共用是 (0,2,0)/(0,3,0)，朝向覆盖是 (0,3,0)/(0,4,0)，稳定压过。所以「共用在前、几何在后」纯粹是可读性选择，挪顺序不会翻车。
- 遗留：模板里**没有** `[data-disabled]` 规则，禁用行目前与可用态同外观（只是拖不动）；已给 MD3 补丁方案（track on-surface 12% / range+thumb 38% / 关掉禁用态 `:hover::after`），等用户确认再落。

### 离线校验「级联」：这次踩到的坑（含对上一份日志的纠正）

- **纠正：`css({raw:[text]})` 不会走编译分支。** `goober/src/css.js` 的分支是 `val.unshift ? (val.raw ? compile(...) : array.reduce(...)) : val` —— 普通对象没有 `unshift`，直接落到 `hash(val)`；`extractCss()` 于是把原文本原样吐出（形如 `.goXXXX raw{0: …}`），**看着像 dump 成功，其实完全没展开**。
  正确写法是**先构造数组再挂 `raw`**：`const a = [text]; a.raw = [text]; css(a);`
- **`extractCss()` 会清空 sheet**（`sheet.data = ''`），连着调第二次就是空串 → 每次 dump 只取一次，之后复用这个字符串。
- 为了验证「共用块是否被朝向块正确覆盖」写了个 cascade resolver（`/tmp/slider-cascade2.cjs`）：解析 `extractCss()` 的扁平规则 → 按「类 + 属性 + 伪类」计数特异性（本仓库选择器全是这两类，个数即 `(0,N,0)`）→ 逐属性取权重最高者。两个坑：
  1. **最右侧那个复合选择器必须精确匹配「目标元素自身」**，不能像祖先那样继续往回扫；否则 `.goRoot[data-orientation]` 会被算到 control/track 头上（表现为 control 也匹配到了 root 的尺寸规则）。
  2. 元素链要照真实 DOM 写：`Root > Control > { Track, Thumb }`。**Thumb 是 Control 的子元素、Track 是它的兄弟**，链上多带一个 track 会把 track 的规则串味到 thumb（曾误判 thumb 有 `border-radius: 999px`）。
- 自检方式：先喂一个已知答案的小样例（`.p [data-part='track'] .range{10px}` vs `.p[data-orientation] [data-part='track'] .range{20px}`，期望 20px），resolver 跑对了再上真实模板 —— 避免用坏了解析器去证明代码没问题。
- 校验结论：横向/竖向每条规则都按预期落位；竖向 thumb 的 `top:auto; left:50%; width:250%; height:auto` 确实压过共用块的 `top:50%; height:250%`；`tsc -p tsconfig.app.json` 仍只剩 `libs/components/Menu.tsx` 空桩的 TS6133。
