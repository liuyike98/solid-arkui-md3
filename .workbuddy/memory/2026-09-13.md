- 修法：`.ripple` 用 `position: absolute; inset: 50% auto auto 50%; width/height: 250%; translate: -50% -50%; border-radius: 50%`。

## 验证结论（写进 skill 了）

- 用 babel-preset-solid 编译最小用例确认：`<Comp ref={ref} />`（`let ref` 可变绑定）会编译成赋值函数，Solid 的 `spread` 对 `ref` 执行 `value(node)`；Ark 的 `CheckboxRoot` 把 `ref` 留在 `labelprops` 随 `mergedProps` spread 到 `<ark.label>`，且 spread 早于 children 渲染 → **`parent={ref}` 确实拿到 label，链路成立**。
- 副作用：hover/按压的触发范围从 40px 圆变成整个 root（含文字）。
- goober 产出确认：`.goRoot .ripple{...}` 特异性 (0,2,0) > Ripple 自身 `.<hash>` (0,1,0)，覆盖稳。

## 定位：`parent={ref}` 为什么点 label 不触发水波纹（非 Ark 问题）

- 现象：点图标有波纹，点 label 文字没有。
- 根因链（读源码定的，不是猜的）：
  1. `<Ripple parent={ref} />` 编译成**静态值** `parent: ref`（`let` 变量不是 signal，编译器不做 getter），props 对象创建时即定格。
  2. Solid `spread`（`web.js:305-313`）里 **children 的 render effect 注册在 ref 之前**，而 `createRenderEffect` 是立刻嵌套执行（`solid.js:220`）→ children 先渲染。
  3. `onMount` 属 `createEffect`（`solid.js:227`），在批次里 `Effects.push` 排队延后 → 但它读到的是 props 上已定格的 `undefined`。
  4. Ripple 于是走 `props.parent ?? container.parentElement` 兜底 → parent = Control(18px) → 只有点图标区域才冒泡到它。
- 修法：`const [root, setRoot] = createSignal<HTMLLabelElement>()` + `ref={setRoot}` + `parent={root()}`；编译产出确认为 `ref: setRoot` 与 `get parent(){ return root() }`，读值推迟到 onMount，此时 ref 已赋值。
- 通用规则：给子组件传 DOM 元素时，prop 必须可延迟读取（getter/accessor），别传裸变量 —— 这也是 Ark/zag 通篇用 `MaybeAccessor` 的原因。可选改进：让 Ripple 的 `parent` 接受 `MaybeAccessor<HTMLElement>`，从库层面消掉这个坑。
- 用户本轮还把 root 改成 `display: flex`（整行点击区），并注释掉了红色调试底。

## 决策：移除 Ripple 的宿主状态属性通道

- 用户判断"和 Ark 的 data- 重复了"，同意移除。改动（`libs/components/Ripple.tsx`）：
  - `hovering`：删掉 `parent.toggleAttribute('hover', force)`，并把判断合并成一个 early-return `if (props.disabledHover || !pointerFine.matches || event.pointerType !== 'mouse') return;`
  - `down`：删掉 `parent.setAttribute('pressed')` / `container.classList.add('pressed')` 以及那对 document 上 pointerup/pointercancel 清理监听（它们唯一作用就是清这两个标记）→ 只剩 `if (event.button !== 0) return; start(event);`
  - `disabledHover` 语义保留（只管自带 hover 图层）
- 依据：grep 全库 `[hover]` / `[pressed]` / `.pressed` 零消费者；该写法来自 mdui shadow DOM 时代（`dist/` 里旧 CSS 可见 `.mdui-switch[hover]`、`.mdui-button--tonal[hover]:not([pressed])` 这类跨边界通信），light DOM + Ark `data-*` 下确实冗余。
- 代价：MD3"按住时 10% pressed 层"没有现成信号了（Ripple 波纹是**松手才播**：mouse 走 pointerup、touch 走 touchend）→ 将来要补得用 `:active` 或重新引入状态输出。
- 类型检查通过（仅剩 App.tsx 历史遗留的未使用 `createSignal`）。

## 修复：indeterminate ↔ checked 无动画

- 原因：短横线用 `display: none/block` 切换、indeterminate 下勾也是 `display: none` —— **`display` 不可动画**，所以是硬切。
- 改法：两者常驻渲染，改由 opacity + transform 交叉淡入淡出。现在 `[data-part='indicator'] svg` 基础态 `opacity: 0; transform: scale(0.7)`，仅 `[data-state='checked']` 拉满；`::before` 基础态 `opacity: 0; transform: scaleX(0.4)`，仅 `[data-state='indeterminate']` 拉满（各自 `transition: opacity 100ms, transform 200ms`）。
- 状态矩阵：unchecked 两者都隐藏；checked 只有勾；indeterminate 只有短横线（勾保持基础隐藏态，不需要额外规则）。
- 注意 `[data-part='indicator'] { display: block }`（覆盖 Ark 的 `[hidden]`）必须保留，否则未选中时整个 indicator 在渲染树外，勾淡入同样不会过渡。
- 副作用：短横线的伪元素现在始终参与渲染（无 layout 影响，绝对定位 + 10×2）。
