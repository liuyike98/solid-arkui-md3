## 定位：`parent={ref}` 为什么点 label 不触发水波纹（非 Ark 问题）

- 现象：点图标有波纹，点 label 文字没有。
- 根因链（读源码定的，不是猜的）：
  1. `<Ripple parent={ref} />` 编译成**静态值** `parent: ref`（`let` 变量不是 signal，编译器不做 getter），props 对象创建时即定格。
  2. Solid `spread`（`web.js:305-313`）里 **children 的 render effect 注册在 ref 之前**，而 `createRenderEffect` 是立刻嵌套执行（`solid.js:220`）→ children 先渲染。
  3. `onMount` 属 `createEffect`（`solid.js:227`），在批次里 `Effects.push` 排队延后 → 但它读到的是 props 上已定格的 `undefined`。
  4. Ripple 于是走 `props.parent ?? container.parentElement` 兜底 → parent = Control(18px) → 只有点图标区域才冒泡到它。
- 修法：`const [root, setRoot] = createSignal<HTMLLabelElement>()` + `ref={setRoot}` + `parent={root()}`；编译产出确认为 `ref: setRoot` 与 `get parent(){ return root() }`，读值推迟到 onMount，此时 ref 已赋值。

## 修复 Slider 竖向不显示

- 症状：`<Slider orientation='vertical' />` 完全看不见（演示里用户原本在 Row 里放了一个 180px 的**兄弟**空 div，不是包裹容器）。
- 根因（3 条，串在一起才是全 0）：
  1. **竖向 root 的 `height: 100%` 拿不到确定高度**。父级是 flex row（`align-items: center`），高度由内容决定 → 百分比高度按 auto 解算 → root 高度 0；横向没这问题是因为厚度 `height: 8px` 是写死的、长度 `width: 100%` 的百分比相对父级**宽度**（宽度不像高度那样有 auto 循环）。
  2. 竖向缺 control/track 的 `height: 100%`（原 CSS 只写在 `&[data-orientation='horizontal']` 块里），整条 root→control→track→range 的百分比高度链断掉。
  3. `.range-left/.range-right` 是横向 flex 写法（`width: var(--slider-thumb-offset-0)` + `height: 100%`），竖向要换轴。
- thumb 的坑（最隐蔽）：Ark 给竖向 thumb 挂的是 `bottom: var(--slider-thumb-offset-0)` + `transform: translateY(50%)`，**不给 left**；而横向那套规则里有 `top: 50%`。两者同时存在时，绝对定位元素 top+bottom 都给定、height 又变 auto → **thumb 被纵向拉长**。所以竖向必须 `top: auto; left: 50%; translate: -50% 0; width: 250%; height: auto`（尺寸基准从 control 高度换成 control 宽度，250% × 8dp = 20dp）。
- 修法：`Slider.tsx` 末尾加一个 `&[data-orientation='vertical']` 块镜像横向（control/track 补 `height: 100%`、track 改 `flex-direction: column-reverse` 让填充从底部往上长、range-left/right 换轴 + `.range-right` 圆角改成 `999px 999px 0 0`）；演示里把 180px 改成**包裹**容器 `verticalBoxClassName { height: 180px }`。
- 校验：goober SSR dump 确认竖向选择器是 `.goX[data-orientation='vertical'] [data-part='control'] …`（0,5,0），比基础规则 `.goX [data-part='control'] …`（0,4,0）高一层属性，稳定覆盖；用 `@zag-js/slider/dist/slider.style.js` 手工驱动 `getRootStyle/getThumbStyle`（伪造 prop/computed/context）能直接打印出真机上会拿到的 inline style —— 查这类"Ark 给了什么、我还缺什么"的问题非常好用。

## Slider 拖拽提示气泡（DraggingIndicator）的入场锚点

- 用户在 `Thumb` 里加了 `<ArkSlider.DraggingIndicator />`，样式写在**横向**块里（`top: -200%`、`min-width: 40px`、`display: flex`、`scale: 0 → 1`、`transition: scale 150ms`、`transform-origin: bottom center`）。反馈：气泡「从右下角出现」，想要「贴着下边缘出现」。
- 根因：Ark 的 `getDraggingIndicatorProps` 给该元素挂 `style: getThumbStyle()`，里面含 **inline `transform: var(--slider-thumb-transform)`**（横向 = `translateX(-50%)`，正是水平居中）。而 **`transform` 属性在变换矩阵里比 `scale` 属性更内层**（矩阵序 `translate·rotate·scale·transform`，作用到点上是从右往左），所以 `scale: 0` 会把这个居中位移**一起塌掉**（位移在 s=0 时对结果无贡献）。于是 `transform-origin` 是相对「未位移的盒子」量出来的：`bottom center` 恰好落在最终盒子的**右下角**。
- 修法：`transform-origin: bottom center` → **`bottom left`**（改一个词）。未位移盒子的左边缘，在最终居中盒子里就是它的底边中心；锚点与内容宽度无关（40px 还是三位数都一样）。
- 实测（无头 Chrome，真实发出的 CSS + Ark 的 inline 样式）：`bottom center` 锚点 X = 0.999 / **`bottom left` = 0.5** / `bottom right` = 1.499；Y 都是 1（底边）。气泡静止盒 (176, -6, 48, 26) 与「居中于滑块」关系不变 → 只动了入场锚点。
- 未引入 `!important`（全库至今零个）。备选：把居中从 `transform` 换成 `translate` 属性（`transform: none; translate: -50% 0`），实测锚点同样 0.5，但要 `!important` 压 Ark 的 inline 样式、且竖向得单独写，未采用。
- 遗留：`[data-part='dragging-indicator']` 的视觉块整个写在横向块里 → **竖向滑块拖拽时气泡是无样式的**；按三段式约定，形状/配色该提到共用段、只留定位在朝向段（未动，等用户确认）。

## 给竖向补上拖拽气泡（放 thumb 右侧）+ 气泡样式提到共用段

- 需求：竖向也要拖拽值气泡，放在 thumb **右边**。
- 关键事实（读 Ark/Zag 源码定的）：
  - `SliderDraggingIndicator` 内部用 `useSliderThumbPropsContext()` 拿 index → **它必须是 Thumb 的子元素**（不是 Control 的兄弟），渲染成 `<ark.span>`。**所以它的包含块是那个 20dp 的 thumb**，Ark 注入的 `inset-inline-start`(横向) / `bottom`(竖向) 的百分比是按 **thumb 自身尺寸**解算，而不是轨道长度。
  - `thumbAlignment` 默认 `"contain"`，`--slider-thumb-offset-N = calc(P% - offsetPx)`，而 `offsetPx = thumbSize*(frac-0.5)`、`P% `又是 `frac × thumbSize` → 两项相减**恒等于 thumb 尺寸的一半**。所以在气泡上写死 `--slider-thumb-offset-0: 50%` 与 Zag 算出的值**数学等价**，只是不再依赖 `thumbSize` 是否已实测（未实测时 Zag 会给出 40% 且把 thumb 设成 `visibility: hidden`）。
  - Ark 的 `--slider-thumb-transform`：横向 `translateX(-50%)`、竖向 `translateY(50%)`（`getRootStyle`）。竖向**不给 `left`**（只给 `bottom`），所以竖向的 `left` 不会被 inline 样式压掉，可以放心写。
- 改法（按三段式约定重组）：
  - ②**共用段**新增 `[data-part='dragging-indicator']`：`--slider-thumb-offset-0: 50%` + 全部视觉（`min-width: 40px` / `padding: 4px` / 999px 圆角 / `#4e4e4e` / 13px / `display: flex` 居中）+ 入场动效（`scale: 0 → 1`、`transition: scale 150ms`、`transform-origin: bottom left`、`&[data-state='open'] { scale: 1 }`）。原先这些全塞在横向块里 → 竖向气泡是无样式的裸 span。
  - ①③朝向段只留定位：横向 `top: -200%`；竖向 `left: calc(100% + 8px)`（`100%` = thumb 宽度 20dp，再留 8dp 间隙）。竖向的纵向居中交给 Ark 的 `bottom: var(--slider-thumb-offset-0)`（已被置成 50% = thumb 高度一半）+ `translateY(50%)`。
- 实测（无头 Chrome，真实发出的 CSS + 复刻的 Ark inline 样式）：
  - 横向：锚点 X=0.5 / Y=1（底边中心）；气泡中心与滑块中心 X 偏差 **0**；气泡底边在滑块上方 14px。
  - 竖向：锚点 X=0.001 / Y=0.5（**左边中点**，正好是横向的镜像）；气泡左边缘 = 滑块右边缘 **+8px**；中心与滑块中心 Y 偏差 **0**。
