# 2026-09-13

## CheckBox：用户改结构后修 ripple 居中

用户自己的改动：去掉背板 div，改成 `<Ripple class='ripple' parent={ref} />` 直接放 Control 内，`ref` 绑 Root(label)，并用嵌套在 rootClassName 里的 `.ripple` 覆盖 Ripple 自身容器样式。

- 修法：`.ripple` 用 `position: absolute; inset: 50% auto auto 50%; width/height: 250%; translate: -50% -50%; border-radius: 50%`。
- 原来不居中的两个原因：① 只覆盖了 `left: 0`，Ripple 自身 `inset: 0` 残留的 `top/right/bottom: 0` 把盒子锚在 padding box 左上角；② `translate: -50%` 单值 == `translate: -50% 0`，**只移 x**，必须写两个值。
- `250%` 是相对 control 的 padding box（14px）算的 → 35px；要正好 40dp 需 `285%`（未改，尊重用户取值）。
- 用户留了 `background-color: red` 调试色，未动（居中验证还用得上）。

## 验证结论（写进 skill 了）

- 用 babel-preset-solid 编译最小用例确认：`<Comp ref={ref} />`（`let ref` 可变绑定）会编译成赋值函数，Solid 的 `spread` 对 `ref` 执行 `value(node)`；Ark 的 `CheckboxRoot` 把 `ref` 留在 `labelprops` 随 `mergedProps` spread 到 `<ark.label>`，且 spread 早于 children 渲染 → **`parent={ref}` 确实拿到 label，链路成立**。
- 副作用：hover/按压的触发范围从 40px 圆变成整个 root（含文字）。
- goober 产出确认：`.goRoot .ripple{...}` 特异性 (0,2,0) > Ripple 自身 `.<hash>` (0,1,0)，覆盖稳。

## 待用户决定的回归项（去背板元素带来的）

1. **键盘聚焦态没了**：原来靠 `[data-part='control'][data-focus-visible] [data-part='backplate']` 的 `color-mix` 图层，元素被删后规则也没了。
2. **disabled 不再屏蔽 hover/波纹**：Ripple 的 `hovering` 不判断 disabled，且原 `[data-disabled] [data-part='backplate']{display:none}` 随背板一起没了 → 现在禁用态 hover 会亮、点击会有波纹。恢复方式：`<Ripple disabledHover={props.disabled} />` 或 CSS `&[data-disabled] .ripple { display: none }`。
